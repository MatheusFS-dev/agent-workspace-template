# Reviewer-Derived Writing Notes

These notes summarize the additional writing failure modes encoded in `reviewer-derived-paragraph-examples.md`. They are not meant to be quoted in manuscripts.

- Broad system claims must match the level of experimental validation actually reported.
- Implemented modules should not be presented as empirically validated unless module-level or task-level evidence exists.
- Interpretability should be scoped as rule inspectability, transparency, expert validation, or user validation, whichever is actually supported.
- Lightweight components should be described with their known operating assumptions and failure modes.
- Motivation paragraphs should connect the selected sensing, modeling, and deployment choices to constraints and trade-offs.
- Unified datasets and label spaces should expose source heterogeneity, class imbalance, annotation quality, rare-class limitations, and underrepresented conditions.
- Custom throughput, latency, power, and energy metrics require workload definitions and measurement protocols.
- Published-method comparisons must distinguish controlled local baselines from contextual related-work comparisons.
- Tables, acronyms, terminology, figure text, spelling, and compiled layout are part of manuscript writing quality.
