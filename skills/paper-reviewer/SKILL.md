# Paper Reviewer

## Route

For an initial new review, require exactly one profile. If no profile or multiple profiles are specified, stop and present this complete list for selection. Do not start a review or combine profiles. Load only the selected profile module plus [Reviewer Voice](references/reviewer-voice.md) and [Canonical Reviewer Style](references/canonical-reviewer-style.md). The canonical review example governs the exact linguistic style of the opening assessment and numbered author-facing comments for every profile. A profile changes the review threshold and recommendation, never the author-facing voice. Shared core references explicitly required under New review may also be loaded:

1. [Grammar, Math, and Formatting Only](references/profiles/grammar-math-formatting.md) — language, equations, notation, units, citations, figures, tables, layout; no scientific merit recommendation by default.
2. [Scientific Initiation Work](references/profiles/scientific-initiation.md) — educational, constructive review of correctness, clarity, fundamentals, and achievable improvements.
3. [Easier Congress](references/profiles/easier-congress.md) — moderate conference threshold for soundness, understandable contribution, sufficient evidence, and presentation.
4. [Hard Congress](references/profiles/hard-congress.md) — selective conference threshold for novelty, rigor, baselines, ablations, statistics, reproducibility, and generalization.
5. [Journal or Letter](references/profiles/journal-or-letter.md) — archival rigor adapted to the declared genre, with journal completeness or a concise, well-supported letter contribution.
6. [Adversarial Reviewer](references/profiles/adversarial-reviewer.md) — strongest defensible rejection-oriented stress test without fabricated or abusive criticism.

A request to review a revision after an earlier review selects Second-Round Review without requiring one of the six initial profiles. Load its module, [Reviewer Voice](references/reviewer-voice.md), and [Canonical Reviewer Style](references/canonical-reviewer-style.md), never the initial profile modules. An explicit switch to another initial profile starts a new review. For a request to edit the latest review, enter edit mode directly, retain its selected profile and canonical reviewer voice, and do not rerun manuscript review. Ask only if the target is ambiguous, prior editable sources are unavailable, or a requested factual assertion is unsupported. In the last case, request evidence or frame the statement as a reviewer concern.

## Second-round review gate

Before a second-round review, obtain the revised manuscript, the author response when available, and the previous comments or review. Ask for the PDF of the last version, a text copy of the prior review, or any information that recovers the previous comments unless that material is already in context. Do not infer what the previous review said. Distinguish a new review round from editing the latest review: a revised manuscript plus a request to check author answers starts a new round; a request to change existing review wording enters edit mode. Follow only [Second-Round Review](references/profiles/second-round-review.md), with exactly two permitted outcomes: rejection or minor rejection. Keep its author-facing text brief and avoid extra considerations or detail. Use [second-round-author-review.tex](assets/second-round-author-review.tex) instead of the initial author template. Keep the editor note concise and confidential.

## New review

Read the supplied manuscript, including relevant figures, tables, equations, references, and context. Follow the requested language; otherwise use the manuscript language, or English if unclear. For every initial scientific profile except Grammar, Math, and Formatting Only, read and apply [Evidence-Driven Scientific Review](references/evidence-driven-scientific-review.md). Build a reverse outline of each section's purpose. Map consequential claims to their actual evidence and distinguish demonstrated results, inference, and missing support. Trace experimental claims across the setup, methods, results, and conclusions rather than reviewing each section in isolation. Check the evidence boundary before stating criticism or praise. Do not load the reviewer-derived example bank for an ordinary review. It is an issue-discovery aid only when the user explicitly requests example-driven stress testing; its candidate angles are not style examples and must never supply manuscript facts.

Make one pass to draft and consolidate comments, then freshly verify every specific claim and location against the manuscript. Use section, figure, table, equation, or algorithm locations rather than page numbers unless requested. Number comments simply and consecutively as 1, 2, 3, merge duplicate concerns, and integrate questions into the relevant comments. Maintain a professional tone. Grammar suggestions should be appropriately tentative. Select a recommendation only when the profile and evidence support one; every principal recommendation reason must trace to a verified major comment. Treat novelty as a recommendation reason only when the review identifies the closest manuscript-cited work, the concrete overlap, and the central contribution that remains unresolved. If the manuscript does not support that comparison, ask the authors to clarify the positioning instead. Never infer venue rules or default to a decision from an earlier paper. Do not create candidate personas or wait for comment approval.

Before adding user-suggested criticism, check its factual premise against the manuscript and any applicable primary source, such as an official venue template. For missing values, spacing, or line-break defects, inspect the rendered PDF and cite a concrete example rather than relying on extracted text alone. If the cause is uncertain, ask a focused question about whether the apparent omission is a rendering error and explain why resolving it matters; request a correction only after the defect is confirmed. If a premise is false, tell the user why rather than inserting the claim. Answer a direct factual question to the user when possible. For an unverified premise, ask the authors to clarify the relevant assumption rather than stating it as a finding. Match the user's requested focus without omitting a material flaw. Present nonessential validation or extensions as optional future work, not a requirement for the current submission.

Deliver immediately: a concise chat summary, a confidential editor-note PDF, a complete author-facing review PDF, and separate copyable TXT versions of both documents. The editor note starts with assessment prose without an Assessment heading. Its Recommendation section contains the decision and principal reasons that materially support the decision, introduced by “The Principal reasons for my decision are:”, with no separate Principal Reasons heading. Keep minor author-facing issues out of the editor note unless they affect the decision. Never reveal the selected profile, skill name, review round, or internal workflow in either document or the chat summary. Do not add a document title or manuscript metadata block to either PDF or TXT file. The author review starts with summary prose without a Summary heading, followed by strengths where appropriate and a single Comments section containing all scientific, textual, mathematical, and formatting findings in one consecutively numbered list. Keep confidential language out of the author document. For the grammar-only profile, state “No scientific merit recommendation assessed” unless the user explicitly requests a recommendation.

Track review rounds as Review 1, Review 2, Review 3, and so on for file naming only. Derive the next number from the available prior review, not from the profile name. Keep the same round number when editing an existing review. Do not print the round number inside either PDF. Number author comments consecutively with Arabic numerals, without prefixed IDs; restart at 1 for each new review round. If a numbered comments section is empty, remove it rather than leave a placeholder.

Write the compiled review using the exact academic prose style demonstrated by [Canonical Reviewer Style](references/canonical-reviewer-style.md), as operationalized by [Reviewer Voice](references/reviewer-voice.md). Do not substitute generic constructive language for close stylistic imitation, and do not transfer manuscript-specific facts from the example. Start each numbered comment directly with prose, without a bold topic label or mini-heading. Preserve every substantive concern, requested action, and factual detail when shortening or recasting a comment. Separate observation from interpretation and required action. Distinguish textual ambiguity from missing scientific evidence. Apply one revision for clarity and proportion, then freshly verify claims, numbers, citations, terminology, and cross-document consistency. Avoid semicolons and em dashes in report prose. Do not expose internal outlines, claim maps, or revision notes.

Before finalizing, classify every numbered comment as an unresolved question, a confirmed defect, or claim overreach, then phrase it in the canonical reviewer voice without imposing a uniform sentence template. Any comment about an unknown method, assumption, denominator, decision rule, selection process, or implementation detail must contain a direct question mark. Multiple closely related questions in one comment are acceptable, as in the canonical example. Replace equipment, metadata, and experiment shopping lists with focused, connected questions that resolve the scientific uncertainty. Preserve the comment's substance and recommendation while changing its phrasing.

Use [editor-note.tex](assets/editor-note.tex) and [author-review.tex](assets/author-review.tex) as starting PDF templates, with [editor-note.txt](assets/editor-note.txt) and [author-review.txt](assets/author-review.txt) for their copyable text versions. For a second-round author report, use the corresponding `second-round-author-review.tex/.txt` pair. Save populated `.tex` sources, PDFs, and TXT files in `review-output/<manuscript-stem>/` by default, named `<manuscript-stem>-review-<N>-editor-note.tex/.pdf/.txt` and `<manuscript-stem>-review-<N>-author-review.tex/.pdf/.txt`; honor another requested destination. Escape manuscript text for LaTeX and preserve mathematical notation. Compile with `latexmk -pdf` or `pdflatex`, remove auxiliary build files, and verify both PDFs are nonempty and text-extractable with `pdftotext`. If tooling is unavailable or compilation fails, report the limitation accurately and retain the editable `.tex` and `.txt` sources. Link all four user-facing files in the response when generated.

## Plain-text output gate

For every review and edit, generate both `.txt` files from the finalized review content, using the matching text templates. They are ordinary UTF-8 text for submission form fields: keep paragraphs and numbered comments, use readable Unicode for math and symbols, and omit LaTeX commands, Markdown, PDF line wraps, page numbers, and discretionary hyphenation. Put one empty line between consecutive numbered items in both author comments and editor recommendation reasons, including second-round items. Compare each TXT file with text extracted from its PDF to catch missing or altered content. Verify that editor-only material never enters the author TXT or PDF. For form-field copying, link the TXT file and never use raw PDF extraction as the copyable version: extraction can join headings to item numbers, collapse math spacing, or break lines inside words. If the user asks to convert an existing review, use its editable sources when available. If only PDFs exist, extract their text, repair wrapping and extraction artifacts, and compare the cleaned text with both PDFs before delivery. Keep the editor and author text separate.

## Edit latest review

Use the retained `.tex` sources for the latest review. Apply requested changes of any size, including adding or removing comments, tone, structure, or recommendation. Preserve unrelated content and follow each requested removal or rewording exactly unless it would introduce a false premise. Check added factual claims against the manuscript or user-supplied evidence. When shortening or converting comments to questions, verify that no concern, requested action, or factual detail was lost. Renumber remaining comments after removals and do not replace a deleted comment with a new concern. Synchronize affected recommendation and summary language across the chat summary, editor note, author review, and both TXT files; remove editor-note reasons that refer only to deleted comments and keep reasons that materially support the decision. Recompile and verify both PDFs, then return the updated summary and links to both PDFs and both copyable TXT files. Do not regenerate comments or require approval of the existing review.
